## 比較と条件

## 修正すべき点

1. **訂正・新しい相談内容を落とさない。** E07は引用に訂正表現が含まれず全体が拒否され、旧通常温度を残したメールに最新訂正原文が併記されます。E19は「御社で調達できますか」をhypotheticalとして黙って除外し、旧客先支給の方式別対応外説明を残しました。変更を確定できない場合も確認事項として保持し、矛盾がある状態で旧条件を確定説明しない必要があります。E19の疑問形を直ちに確定変更と解釈すべきかは曖昧ですが、相談を失って旧方式だけを説明する挙動は問題です。
2. **抽出契約と検証をそろえる。** E09/E13/E14/E18は新規品目の識別用fieldがなく拒否されます。newItems.labelだけでは現行検証を満たさない条件をモデルへの指示が説明していません。E06の「分かりません」、E17の「開示できません」はunknown検査の表現に一致しません。E08は引用に80mmがなく、数値検証で拒否されます。安全な引用・対象検証を維持したまま、指示と受理条件をそろえる必要があります。
3. **会社内分類の解決をサーバー側で行う。** E01/E10は値を抽出できてもcategory=nullで、架空の承認ルールに結び付きません。型番alias等を明示的な会社知識に照合し、分類をモデルの推測へ依存させない修正が必要です。
4. **正しい抽出を確保してから3秒以内を再評価する。** 今回のnone設定だけでは改善を確認できません。出力形式・通信・モデル等の比較は別の固定条件で行い、抽出失敗を速い成功へ数えない必要があります。

この評価中には上記の製品修正を加えていません。修正後の結果は今回の固定版とは別に記録します。
