## 接続する処理

自由文だけを抽出専用adapterへ渡します。質問順・取扱可否・調査開始・メール送信は既存の決定的な処理が担当します。選択・不明・スキップ・フィールド編集ではAPIを呼びません。

OpenAIの[Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create)と[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)の仕様を参照し、`text.format`のJSON Schema、strict=true、store=falseで要求します。store=falseはこのAPIリクエストの保存設定であり、組織全体の情報利用許可を代行しません。

入力は、現在の質問・現在値・最新発言・直前の入力1件・許可属性/カテゴリのみです。APIキーはAuthorizationヘッダーにだけ置き、Cookie、案件所有者、全発言履歴、会社資料本文、写真/PDF、R2キーはモデル入力へ渡しません。外部検索ツールは付けません。

出力は内部契約 `urn:aoki:availability-v2:intake-proposal:1` の変更案です。公開契約版2は変更していません。

- 新規品目の参照名をサーバー発行のitemIdへ変換します。
- 属性辞書、引用の実在、値、単位、数値種別、型番末尾、部品の所有者を検証します。
- 仮定・未確定の変更相談は現在値にせず、原文と対象欄を確認待ちとして保持します。対応欄の明示入力・編集で保留を解消します。既存値を変えるには、対象欄への回答か、同一文上の明示訂正を要求します。
- 不明はunknownに保存します。曖昧な対象・抽出できない条件・不正スキーマを黙って捨てず、その発言を未確認入力として保持します。
- 数値の引用は属性ごとに短く限定します。複雑な言い換え・一文に旧値/新値が並ぶ表現は保守的に拒否することがあります。修正版では原文中の一意の文へ引用を補えるようにし、複数数値・属性違い・別部品・変更否定の拒否は維持します。

## ローカル開発の回数制限解除（2026年11月20日）

ユーザーの承認により、通常プレビューでは `.dev.vars` の `INTAKE_UNLIMITED_LOCAL=true` を有効化しました。`APP_MODE=local-demo` の場合だけ、累計・案件別の回数上限を適用しません。他のAPP_MODEでこのフラグを有効にすると設定エラーです。ローカルWorkerの入口は引き続きループバック限定です。

回数・利用トークンの記録は継続し、既存カウンターをリセットしません。同一操作の再送/同時再送による二重呼出し防止、出力トークン上限、認証失敗/429時の停止も維持します。反映後は開発サーバーを再起動し、`npm run intake:status` の `unlimitedLocal: true` を確認してください。制限を戻す場合はfalseにして既存の回数上限を設定します。過去の40回比較評価runner・台帳は変更しません。

## 設定

`.dev.vars.example`を参考に、Git対象外の`.dev.vars`を作ります。秘密キーをチャットへ貼る必要はありません。許可なしで旧システムのキーや設定を自動コピーしません。今回はユーザーの明示許可による既存キー再利用で、元のenvは変更していません。

| 設定 | 意味 |
| --- | --- |
| `INTAKE_PROVIDER=demo` | 既定。簡易抽出、外部送信0回 |
| `INTAKE_PROVIDER=disabled` | 自由文抽出を停止し、入力保持・メール文を利用 |
| `INTAKE_PROVIDER=openai` | OpenAI用adapterを選択 |
| `EXTERNAL_ENABLED=true` | 外部利用の明示設定。falseなら接続前に拒否 |
| `OPENAI_API_KEY` | この新システム用の利用可能なAPIキー |
| `INTAKE_MODEL` | Structured Outputs対応のモデル名を明示。既定名や自動代替なし |
| `INTAKE_FORMAT` | `full` / `compact`。未指定は従来のfull形式 |
| `INTAKE_REASONING` | `none` / `low`。未指定はモデルの既定設定 |
| `INTAKE_MAX_OUTPUT_TOKENS` | 1〜4096の整数。1回の最大出力トークン数 |
| `INTAKE_UNLIMITED_LOCAL=true` | local-demo専用。累計・案件別の回数上限を解除。未指定/falseなら回数上限を適用 |
| `INTAKE_MAX_CALLS_TOTAL` | 1〜100000の整数。回数制限が有効な場合の累積呼出し予約上限 |
| `INTAKE_MAX_CALLS_PER_CASE` | 1〜20の整数。回数制限が有効な場合の案件ごとの累積呼出し予約上限 |

接続時はキー・モデル・出力トークン上限を明示します。回数制限の解除が未指定/falseなら、累計・案件別の回数上限も必要です。未設定・不正値ではCONFIG_MISSINGとなり、送信予約も作りません。設定例の20回/案件3回/出力1024はデモ用の例で、会社の利用承認値ではありません。

gpt-5.6-terraでは、スキーマを受理し、1件の抽出がHTTP応答全体で2975msだったことを確認しました。日本語品質やp95速度の合格を意味しません。モデルはこの接続コードから自動選定しません。

**呼出し回数と出力トークン数の上限は、課金額そのものの上限ではありません。** 実評価を始める前に、利用するモデルの料金と入力トークン量を踏まえた費用上限、許可データ、会社の外部AI利用方針を設定してください。今回の評価runnerは生成前の入力計数・最大出力分の予約により1米ドル/40生成を制御します。この費用制御は通常プレビューへは組み込んでいません。

## 冪等性・失敗時・停止

`intake_calls`でcaseId＋mutationIdを一意に予約してから呼びます。予約時には案件revision・有効期限・全体停止状態・案件/全体の上限をD1 batch内で確認します。同時再送では一方だけが予約し、他方は409で入力を保持します。

入力内容・質問・revision・モデルが同一の再送では、保存済みの抽出結果または失敗結果を返します。処理中なら再呼出ししません。クラッシュで結果不明の予約も使用回数に算入し、同じmutationIdで再送しても再課金を起こす呼出しをしません。顧客の明示的な再試行は別mutationIdとして上限内で扱います。

ローカル版のOpenAI聞き取りは30秒で中止し、同じ操作の再送は30.5秒まで保留します。時間切れ・接続障害・不正応答の際は、入力から明確に確認できる条件を保存し、呼出し台帳に元の失敗を記録します。レスポンスのincomplete、refusal、不正JSON/契約は呼出しの失敗です。再生成や別サービスへの自動切替は行いません。リダイレクトはmanualで受け、3xxは失敗として認証ヘッダーを別URLへ転送しません。

401/403と429では全体停止状態を保存します。原因を確認するまでは、別案件でも追加のモデル呼出しをしません。500等も同一入力の自動再生成はしません。

```bash
npm run intake:status
# 設定・利用枠を修正し、明示的に再開する場合だけ
npm run intake:resume
```

再開はローカル管理者認証とOrigin/CSRF検証を通します。累積使用数はリセットしません。案件削除後は私的な抽出キャッシュを消し、予約メタデータも90日後に削除します。個人情報を含まない累積カウンタだけを別テーブルへ残すため、保管期限処理で利用上限がリセットされません。APIが返した利用トークンは記録し、返らなかった利用量は不明のままです。モデルの生応答・キー・原文は監査ログへ書きません。

未確認の発言は画面とメール文へ保持します。仮定扱いの相談の欠落と旧構造化値の併記を修正しました。確認待ちの間はメールに旧構造化値・旧判断を記載せず、結果の分野判定と「確認した条件」も保留します。未解釈の追加条件が残るときは、旧条件だけを使って個別依頼を肯定・否定しません。全く同じ発言を再入力して抽出と検証に成功した場合、その発言の未確認状態を解消します。それ以外の未確認入力は残します。

## 検証と残件

ローカル試験では、OpenAI応答をテスト内で差し替えています。実Worker・D1を通した予約、同時送信、再送、上限、認証/429停止、クラッシュ回復、削除と使用数維持を検証します。外部送信はありません。

`npm run eval:live`は既定で通信せず終了コード2です。明示の`--live`で評価runnerを実行し、永続予約・同一ID再送禁止・固定digest・1米ドル/40生成上限を適用します。修正版の代表10件は`--phase repair`で実施しました。以前の24要求も同じ累計予算へ算入し、修正フェーズは最大10生成です。最終補強後はdigest不一致で追加通信を拒否します。[評価報告](LIVE-REPAIR-20261116.md)を参照してください。

抽出契約・分類接続・最新条件の保持は修正し、固定回帰と代表例を再検証しました。3秒以内という基準は11月16日の実測に適用した速度目標です。30秒は現在のローカル版の応答期限です。独立した未知相談での評価が残ります。会社の実資料との判断一致、外部検索、本文取得、画像/PDF解析、公開・旧入口切替は今回の段階4の範囲外です。
