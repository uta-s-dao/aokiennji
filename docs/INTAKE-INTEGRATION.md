# 自由文抽出のOpenAI接続

設計版1.1の段階4。接続コードとローカル試験を実装しました。**実APIへの送信とモデル品質評価は未実施**です。現在の起動設定はdemoで、キーも実モデル名も設定していません。

## 接続する処理

自由文だけを抽出専用adapterへ渡します。質問順・取扱可否・調査開始・メール送信は既存の決定的な処理が担当します。選択・不明・スキップ・フィールド編集ではAPIを呼びません。

OpenAIの[Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create)と[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)の仕様を参照し、`text.format`のJSON Schema、strict=true、store=falseで要求します。store=falseはこのAPIリクエストの保存設定であり、組織全体の情報利用許可を代行しません。

入力は、現在の質問・現在値・最新発言・直前の入力1件・許可属性/カテゴリのみです。APIキーはAuthorizationヘッダーにだけ置き、Cookie、案件所有者、全発言履歴、会社資料本文、写真/PDF、R2キーはモデル入力へ渡しません。外部検索ツールは付けません。

出力は内部契約 `urn:aoki:availability-v2:intake-proposal:1` の変更案です。公開契約版2は変更していません。

- 新規品目の参照名をサーバー発行のitemIdへ変換します。
- 属性辞書、引用の実在、値、単位、数値種別、型番末尾、部品の所有者を検証します。
- 仮定は現在値にしません。既存値を変えるには、対象欄への回答か、引用上の明示訂正を要求します。
- 不明はunknownに保存します。曖昧な対象・抽出できない条件・不正スキーマを黙って捨てず、その発言を未確認入力として保持します。
- 数値の引用は属性ごとに短く限定します。複雑な言い換え・一文に旧値/新値が並ぶ表現は保守的に拒否することがあります。これは実モデルの未知相談評価で確認する残件です。

## 設定

`.dev.vars.example`を参考に、Git対象外の`.dev.vars`を作ります。秘密キーをチャットへ貼る必要はありません。旧システムのキーや設定を自動コピーしません。

| 設定 | 意味 |
| --- | --- |
| `INTAKE_PROVIDER=demo` | 既定。簡易抽出、外部送信0回 |
| `INTAKE_PROVIDER=disabled` | 自由文抽出を停止し、入力保持・メール文を利用 |
| `INTAKE_PROVIDER=openai` | OpenAI用adapterを選択 |
| `EXTERNAL_ENABLED=true` | 外部利用の明示設定。falseなら接続前に拒否 |
| `OPENAI_API_KEY` | この新システム用の利用可能なAPIキー |
| `INTAKE_MODEL` | Structured Outputs対応のモデル名を明示。既定名や自動代替なし |
| `INTAKE_MAX_OUTPUT_TOKENS` | 1〜4096の整数。1回の最大出力トークン数 |
| `INTAKE_MAX_CALLS_TOTAL` | 1〜100000の整数。ローカルDB内での累積呼出し予約上限 |
| `INTAKE_MAX_CALLS_PER_CASE` | 1〜20の整数。案件ごとの累積呼出し予約上限 |

接続時は、キー・モデル・3種類の上限をすべて明示します。未設定・不正値ではCONFIG_MISSINGとなり、送信予約も作りません。設定例の20回/案件3回/出力1024はデモ用の例で、会社の利用承認値ではありません。

モデルの互換性・日本語品質・3秒制限での速度は実APIで未確認です。モデルはこの接続コードから自動選定しません。

**呼出し回数と出力トークン数の上限は、課金額そのものの上限ではありません。** 実評価を始める前に、利用するモデルの料金と入力トークン量を踏まえた費用上限、許可データ、会社の外部AI利用方針を設定してください。現在はその実評価を行っていません。

## 冪等性・失敗時・停止

`intake_calls`でcaseId＋mutationIdを一意に予約してから呼びます。予約時には案件revision・有効期限・全体停止状態・案件/全体の上限をD1 batch内で確認します。同時再送では一方だけが予約し、他方は409で入力を保持します。

入力内容・質問・revision・モデルが同一の再送では、保存済みの抽出結果または失敗結果を返します。処理中なら再呼出ししません。クラッシュで結果不明の予約も使用回数に算入し、同じmutationIdで再送しても再課金を起こす呼出しをしません。顧客の明示的な再試行は別mutationIdとして上限内で扱います。

3秒でAbortSignalを中止し、再生成・高額モデルへの切替・別サービスへの自動退避をしません。レスポンスのincomplete、refusal、不正JSON/契約は失敗です。リダイレクトはmanualで受け、3xxは失敗として認証ヘッダーを別URLへ転送しません。

401/403と429では全体停止状態を保存します。原因を確認するまでは、別案件でも追加のモデル呼出しをしません。500等も同一入力の自動再生成はしません。

```bash
npm run intake:status
# 設定・利用枠を修正し、明示的に再開する場合だけ
npm run intake:resume
```

再開はローカル管理者認証とOrigin/CSRF検証を通します。累積使用数はリセットしません。案件削除後は私的な抽出キャッシュを消し、予約メタデータも90日後に削除します。個人情報を含まない累積カウンタだけを別テーブルへ残すため、保管期限処理で利用上限がリセットされません。APIが返した利用トークンは記録し、返らなかった利用量は不明のままです。モデルの生応答・キー・原文は監査ログへ書きません。

未確認の発言は画面とメール文へ保持します。未解釈の追加条件が残るときは、旧条件だけを使って個別依頼を肯定・否定しません。全く同じ発言を再入力して抽出と検証に成功した場合、その発言の未確認状態を解消します。それ以外の未確認入力は残します。

## 検証と残件

ローカル試験では、OpenAI応答をテスト内で差し替えています。実Worker・D1を通した予約、同時送信、再送、上限、認証/429停止、クラッシュ回復、削除と使用数維持を検証します。外部送信はありません。

`npm run eval:live`は現在、実評価未実施を明示して終了コード2を返すガードです。実モデル評価を実行するrunnerや、未知20相談の評価完了を装いません。

次に必要なのは、実際に使うモデル・新規キー・会社のデータ利用許可・評価費用上限を設定し、実モデルで表現違い・訂正・部品別条件・3秒期限を検証することです。会社の実資料との判断一致、外部検索、本文取得、画像/PDF解析、公開・旧入口切替は今回の段階4の範囲外です。
