# UTA-13 ドメイン・実メールに依存しない受入記録

2026-10-21、`origin/main` の `9caa094a89e2416291fba69f411d771b1e060804` を基点に検証。今回の変更は依存更新とE2Eの待機順の修正で、本番への配置・DNS変更・実メール送信は実施していない。UTA-13全体の完了・正式公開可の判断は保留する。

## 今回の修正

- Viteを8.0.0から8.3.5へ更新し、関連するRolldown等のlockfileを更新した。
- Satori配下のfflateを0.7.3から同じ0.7系の修正版0.7.5へoverrideした。Satori自身と、その配下の`@shuding/opentype.js`の両方で0.7.5を確認した。[公式アドバイザリ](https://github.com/advisories/GHSA-px8p-9vwx-vf98)のZIP64無限ループ対策。
- 会話記録・情報源検証記録のJSONダウンロード試験で、ボタンを押す前にイベント待機を`await`して停止する記述を3か所修正した。待機Promiseを先に登録し、クリック後に完了を待つ。画面の機能変更はない。
- 一連のE2Eが同じクライアントのログイン上限を消費し、後半の業務試験が429になることを再現した。独立した業務フローにテストID由来の検証用IPv6アドレスを割り当てた。アプリの頻度制限は変更せず、DB統合で上限を検証する。ストリーミング画面試験は操作前にタブを前面化し、ボタンをキーボードで操作する。

## 現在の依存監査

更新前と更新後に`npm audit --omit=dev --json`を実行した。検出ノード数は14（high 7 / moderate 7）から10（high 7 / moderate 3）へ減少。親パッケージへの伝播を含むため、10種類の独立した実行時脆弱性という意味ではない。監査コマンドは引き続き終了コード1であり、指摘ゼロとは扱わない。

残る根本の指摘は以下の2種類。確認時点で公式修正版がないため、監査の自動提案によるvinext・Mammothの大幅な旧版への変更は行わなかった。

| 対象                        | 依存経路と現在の評価                                                                                                                                                                                                                                                                                 | 残る対応                                                                                                                 |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| braces 3.0.3 / high         | `vinext → vite-plugin-commonjs → vite-plugin-dynamic-import → fast-glob → micromatch → braces`。プラグインの`transform`でソースのdynamic importからglobを作り、ビルド対象を検索する経路。深く入れ子になったパターンによるスタック枯渇。[公式指摘](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) | ビルドするコード・設定は信頼できるものに限定し、上流修正版を追跡する。未信頼リポジトリのビルドに安全という評価ではない。 |

今回生成したWorkerの169個のsourcemapに、braces・sprintf-js・argparse・fast-glob・micromatch・上記2プラグインのsourceは検出されず、配信JS中にもこれらの名前は検出されなかった。Mammothの`lib/index.js`は検出されることを対照確認した。ただしvinext/RSCプラグインからsourcemap警告が出ており、この検査だけを完全な到達不能の証明とは扱わない。上記の実際の読込元と併せた、今回のビルドに限る評価である。

- ユーザー指定により、会社ドメイン、Web用DNS・HTTPS・正規URL・転送、Resend送信元認証・実受信は後日まとめて実施する。
