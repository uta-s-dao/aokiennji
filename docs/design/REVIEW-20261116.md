## 代表相談の流れ

以下はメールから抽出した構造を使う設計例。実メールへの返信ではなく、現在の取扱を保証するものでもない。結果の肯定部分には有効な会社承認ルールがある場合を明記する。

### A 型番を読み取れない交換部品

1. 顧客：「この写真のスイッチを探しています。型番がはっきり読めません」。
2. 写真と対象説明を保持。識別に有用で未回答なら「何の装置に付いている部品ですか？」を一問だけ聞く。完全な型番入力は強制しない。
3. 調査では判読できた箇所・候補・未確定を区別する。
4. 承認根拠がない場合の結果：「型番と当社の取扱可否は確認が必要です。写真と装置の情報を含めてメール相談できます」。
5. メールに判読不能箇所を残し、候補型番を確定条件にしない。写真の再添付が必要なことを案内する。

### B 図面を使う製作相談

1. 顧客：「図面の架台を製作したいです。塗料は支給します。来月上旬を希望します」。
2. 図面、fabrication、支給塗料、希望時期を保存。材料そのものまで客先支給とは推定しない。図面全体か一部かが曖昧なら「図面のどの部分の製作をご希望ですか？」を聞く。
3. 一括調査で分野の根拠、個別の寸法・重量・塗装・依頼範囲を確認。図面の存在だけで強度・製作性を保証しない。
4. 有効な分野承認ルールがある場合の結果：「架台製作はご相談の対象です。今回の仕様での製作と希望時期への対応は担当者確認が必要です」。scopeAssessment=in_scope、verdict=needs_review。
5. メールは製作範囲、図面版、塗装・支給品、希望時期、未確認事項を含める。

### C 材料調達と加工

1. 顧客：「このリング材を支給するので穴加工してほしいです」。processing＋customer_suppliedとして保持。
2. 現在有効な方式別対応外ルールがあれば、その対象・方式に限定して説明。過去メールの断りだけなら現在の可否は確認待ちとする。
3. 顧客が「材料も御社で調達できますか？」と明示変更したら、company_sourcedへ更新し、旧方式の結果を無効化する。
4. 新方式に承認根拠がなければ「材料調達と加工をまとめた対応は、担当者確認が必要です」。旧方式の不可を転用せず、可能とも断言しない。
5. メールに現在希望する方式と材料指定・加工範囲を保持する。旧方式を現在の依頼として復活させない。

## 変更する契約と受入条件

- 既存の4プロフィールは識別方法として維持し、別軸のrequest_scopeとmaterial_supplyを属性辞書へ追加。製作範囲・除外・支給品・図面版・塗装も部品ごとの属性として定義する。
- ItemResultにscopeAssessmentを追加。今回のverdictと別に、分野の公開理由・根拠を保持する。
- CapabilityRuleにassessmentScopeを追加。分野承認を個別依頼の肯定へ流用しない。両者に矛盾する肯定を拒否する。
- 分野の肯定も撤回・期限・revisionに従う。メール生成時も再検証する。
- I13〜I15、S09〜S10、R17〜R21を追加。仕様・型・例・実装指示を一緒に更新する。

二段階、一問中心、最大6問、未知・スキップの尊重、結果からの明示修正、メール作成＋コピーという流れを維持する。分野だけ確認できた案件と、個別依頼まで判定できた案件は別に集計する。
