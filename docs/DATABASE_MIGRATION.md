# UTA-8：Postgresへの移行

アプリの永続データと管理・匿名セッションはSupabase Postgresを使用する。`DATABASE_URL` がない／接続できない場合は失敗し、SQLiteや一時ファイルには保存しない。開発DBの自動コピーと起動時のデモ登録は廃止した。

## 接続と権限

サーバーの接続に `postgres` ドライバーを使い、transaction poolerに合わせてprepared statementを無効化する。最大4接続、非ローカル接続は証明書検証付きTLS。ブラウザーに接続文字列・DBキーを渡さない。`DATABASE_MIGRATION_URL` はマイグレーション専用で、Webサーバーに設定しない。

業務テーブルはAPI非公開の `app_private` に置く。全テーブルでRLSを有効化し、`anon`／`authenticated`／PUBLICのスキーマ・テーブル権限を取り消す。アプリはサーバーで署名CookieとDBのセッション期限・種類を照合し、会話は所有者を確認する。ログアウトはDBのセッションを削除し、管理パスワード・署名鍵の変更も既存Cookieを無効にする。Supabase Authの利用者登録／メール送信には依存しない。

本番では管理用DB接続をアプリへ配らず、別途作成した専用LOGINロールを `aoki_app` のメンバーにする。LOGINのパスワードは秘密管理で生成・保管し、Gitへ記録しない。`aoki_app` はNOLOGIN／NOBYPASSRLSで、業務テーブルのCRUDのみを持つ。DDLとマイグレーション管理スキーマの権限を持たない。DBレベルのこのロールはブラウザー利用者を意味せず、個々の操作の認可はサーバーで行う。

## ローカルでの再現

```bash
node scripts/supabase-local.mjs start
node scripts/supabase-local.mjs status
npm run db:local:migrate
npm run test:db
# Browser tests (if the OS browser dependencies are installed):
npm run test:e2e:db
```

`database-local.mjs` は専用秘密ファイルにあるループバックのDB接続だけを子プロセスへ渡す。本番接続は参照しない。テストは各ケースの開始時に `app_private` を空にして架空データを投入するため、共有の検証DBや本番で実行しない。単体・統合試験とE2Eは同時に実行しない。マイグレーションはトランザクションと適用履歴で再実行を管理する。

開発サーバーもこのラッパーから `node scripts/database-local.mjs npm run dev` で起動できる。通常の `npm run dev` は環境変数 `DATABASE_URL` を別途設定する。空のDBでUIデモが必要な場合のみ `seedDemoData()` を明示的に呼ぶ。これは架空データであり、本番への登録対象ではない。

## データ・競合の扱い

- SQLマイグレーションに主キー、外部キー、一意索引、検索用索引を定義する。挿入順は明示的なidentity列で維持する。
- 業務オブジェクトは既存のJSON形式を保ち、検索・参照・競合判定に必要な列を別に持つ。SQLでJSONの妥当性も検査する。日時の業務表現はUTCのISO文字列、DBの記録時刻はTIMESTAMPTZ、セッション期限はミリ秒のBIGINT。
- 円単位の見積金額は既存の安全な整数検証を維持。費用予約は整数micro-yenで、同時予約・二重精算をDBの条件付き更新とロックで保護する。提供元ごとの料金・月額停止への接続と管理画面はUTA-9。
- 受付と見積依頼には `Idempotency-Key` が必要。同一キー・同一内容は同じ結果を返し、内容が異なれば409。画面は通信エラー後の再送で同じキーを使う。受付、監査、返信キーは同じトランザクションで保存する。
- 頻度制限は単一の条件付きUPSERT。見積状態変更・取込プレビューの消費・調達記録・サイト編集はトランザクションと対象ごとのロック／版番号で保護する。
- 非同期呼出元をServer Component、API、同期処理、AI記録、テストまで更新する。保存失敗を成功レスポンスとして返さない。

## ファイルと本番データ

取込CSV・Excel・PDFの原本は永続保存せず、解析結果と期限付きプレビューだけをDBへ保存する。画像はメタデータ除去・サイズ制限後のJPEG／WebPだけを非公開DBのBYTEAへ保存する。画像IDを知っていても、公開中のサイトで参照されない画像は管理認証が必要。Storageへ原本を複製する処理はない。原本を保持する業務要件が決まった場合は会社質問票Q016／Q017の保存範囲・期間の回答に従って追加する。

本番適用前に、会社承認済みの設定・商品・資料を選別して管理機能から登録する。開発SQLiteの一括コピー、検証会話／見積の取込、デモ投入は行わない。会社が承認するまで未回答の価格・納期・保存条件を正式な条件へ変えない。

ローカル試験はCloudflareでの実配置・本番再デプロイ試験を代替しない。DB適用とアプリ公開は別工程として記録する。SQLiteの複製と現行データ層を混在させる旧会話シミュレーション6本は、`DATA_DIR`だけでDBを分離できないため起動直後に停止する。代替は分離済みSupabaseの単体・統合・E2E試験。読み取り専用の`audit-supplier-sites.ts`は過去SQLiteスナップショットの監査専用として残す。
