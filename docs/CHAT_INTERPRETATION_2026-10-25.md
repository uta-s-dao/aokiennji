# 商品名称の意味解釈と仕入先資料の参照

ユーザーが「OpenAI APIに分別を任せる」方向と、指定Excelを必要に応じて登録・参照する修正を承認。

- 発言の解釈はOpenAIの構造化出力を使い、回答生成の`responseProvider=local`から独立。`OPENAI_INQUIRY_MODEL`（既定gpt-4.1-mini）を使用し、既存の利用枠・予約・実績記録を通す。APIキーなし／枠不足／応答不正の場合は確認へ戻し、質問済みという理由で次の段階へ進まない。
- 最新発言と会話履歴から、注文型番、商品名・シリーズ名・材質表示、明示メーカー、数量訂正、見積不要を区別。原文にない名称・メーカー・数量根拠は採用しない。AIが商品名称と分類した文字列を正規表現で勝手に型番へ格上げしない。
- 商品名称は登録商品へ照合し、一致しないことを販売不可・在庫ありの根拠にはしない。仕入先資料は取扱分野の参考に限定し、商品・在庫・確保数量とは区別。
- 指定ファイル「【重要】36期_売買集計表（仮）.xlsx」は1シートの仕入先一覧。既存パーサーで有効41件、警告0件。読み取る列は仕入先・取扱い品・HPのみ。月別金額・工番・数式は取り込まない。原本、仕入先名、URLはGit・公開回答へ掲載しない。
- `scripts/import-supplier-workbook.ts`でプレビュー後、`--apply --approve-fields`により非公開supplier_knowledgeへ登録。リモートDBは追加の`--production-approved`が必要。同名情報源への再取込は置換、重複行は既存機構で排除。

検証：関連40件成功。実OpenAIで回答方式localのまま「耐熱ガラス→BOROFLOAT® 33→5枚へ訂正・見積不要→在庫質問」の4往復成功。実Excel41件を用い、取扱分野の参照、仕入先名・URLの非漏洩、在庫未確認を検証。データ無効化後の履歴再評価と話題変更も検証。

設計参照：[OpenAI Structured outputs](https://developers.openai.com/api/docs/guides/structured-outputs)。構造化出力は形式の保証に用い、販売可否・在庫の根拠はDB側で確認する。
