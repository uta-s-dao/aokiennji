# 未登録商品の検索・調達相談（2026-10-15）

台帳にない型番でもWeb上の商品・購入窓口を調べ、当社への取り寄せ・見積相談につなげる。単に「登録情報では取扱いを確認できません」と答えて終わる経路を改善した。

## 確認した原因

- `http://localhost:3212` は移行DBのコピーを使う会話試験用サイト。起動スクリプトがJev・Web検索・担当者向け調査を無効にしていた。
- 従来のWeb検索はExa/Tavilyのみで、両方のキーが未設定だった。OpenAIとJevのキーは存在し、今回の実接続は両方成功した。
- 型番付きの価格・取り寄せ質問が検索を通らず、取扱分野が分かっている場合にも検索が省かれる経路があった。
- 10月7日の保存済み会話は当時の回答。過去の記録本文は書き換えていない。

## 実装

1. 未登録の型番は、既存の仕入先ドメインに制限せず検索する。検索方式にOpenAIのResponses API Web検索を追加した。実際の検索出典にあるURLのみを使う。
2. 商品ページを取得し、型番の完全一致を確認する。ハイフンと空白の表記差は許容し、異なる末尾型番は除外する。Jevが同一商品かを追加判定する。
3. 購入窓口を確認できた商品は「当社でお取り寄せ・お見積りのご相談を承ります」と案内する。商品掲載のみ・調査失敗・候補不明はそれぞれ区別し、成功したようには回答しない。
4. 掲載先、型番の一致判定、取得できた掲載価格・在庫区分は管理画面のAI調査メモに保存する。価格は型番が一致する商品構造化データから取得する。別商品・別サイズの価格を転用しない。
5. お客様には仕入先URL・仕入価格を出さず、販売価格は担当者が見積で確定する。検索だけで登録商品を承認したり、実際の発注を行ったりはしない。
6. 数量・価格の追加質問でも対象型番を保持し、同一会話の同一型番の検索結果は15分間再利用する。相談内容・数量・配送先を見積依頼フォームへ引き継ぐ。
7. 検索・ページ確認の所要時間に合わせて、検索有効時のサーバー応答期限を55秒、ブラウザの通信期限を65秒にした。

主な実装：`lib/server/sourcing.ts`、`lib/server/search-openai.ts`、`lib/server/chat.ts`。

## 掲載価格の取りこぼしとAI利用詳細の整理

17:30:29の保存済み回答では、マツヨシと理科ナビに価格があっても調査メモに保存されていなかった。従来は型番が一致するProductのJSON-LDからのみ価格を取得していたため。両サイトの商品本文の価格にも対応し、主商品の型番が一致する範囲だけを読む。関連商品一覧の価格は流用しない。

- [マツヨシ](https://www.matsuyoshi.co.jp/item/00210791/)：希望小売価格／参考価格720円（税抜き）、792円（税込み）。
- [理科ナビ](https://www.rikanavi.com/product/31310103)：標準価格720円（税抜）。

いずれも取得した実ページのHTMLで抽出を確認した。参考・標準価格は担当者向けの調査結果として保存し、仕入価格や当社販売価格として自動採用しない。保存済みの過去の調査メモは変更していないため、追加した価格取得は次回の検索から適用する。

同回答にはprocessing・replyToIdが保存されていない。AI利用詳細の「未記録」はこの記録不足を表しており、AIの処理が難しかったという判定ではない。画面は会話・回答の詳細・調査メモという構成を維持し、次を整理した。

- 回答方法は回答本文の下に1回表示。準備・判定とWeb検索の重複欄、未記録の項目、通常の採用結果を言い直す説明文を省略。
- AIの用途・提供元・モデル・採用結果を残す。商品検索と型番の一致判定は実際の処理に合う用途名で表示。通信・トークン情報は折り畳みに集約。
- 候補カードのURL・商品判定・掲載価格・在庫・調達条件の編集は維持。同じ確認状態はカード内で1回にまとめ、一致率の繰り返しと空の仕入価格欄を省略。次の確認手順は折り畳み。

検証：型チェック成功、関連単体テスト13件成功、会話履歴・AI利用詳細・調達条件編集のE2EはPC／モバイル計8件成功。ブラウザー試験は既存の検証用ライブラリを`LD_LIBRARY_PATH`で指定して実行した。外部検索・Jevの実APIは今回再実行しておらず、両販売サイトから取得したHTMLでの価格抽出と、モックを使った保存・非公開・価格転用防止の検証を行った。

## 部分一致の候補検索（2026-10-16）

商品検索の問い合わせに、元の型番と区切り文字を空白へ置き換えた表記を含める。検索結果ページはページ上の型番完全一致だけで除外せず、最大5ページをJevの同一商品判定へ渡す。Jevにはサイズ・容量・文字数字の接尾辞まで指定型番と一致するよう採点基準を明示し、0.8以上を一致候補にする。商品ページ本文の抜粋は完全型番がなければ型番の部分文字列付近から作る。

Jevが未設定または利用できない場合は、従来どおりページの型番完全一致を確認できた候補だけをローカル判定で採用する。Web検索自体はOpenAI／Exa／Tavilyの設定済みプロバイダーが行い、JevのSystem One APIは検索結果の判定に使う。今回、広い候補をJevへ渡す流れは実APIでは再評価していないため、精度を実測済みとは扱わない。
