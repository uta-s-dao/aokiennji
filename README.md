# AOKI ENG — 企業サイト・商品相談

アオキエンジ株式会社のサイト刷新と、複数情報源を使う商品相談・見積・注文管理アプリです。

ノートPCからデスクトップへの移行は [開発引き継ぎ資料（2026-10-14）](docs/DESKTOP_HANDOFF_2026-10-14.md) を参照してください。現在のブランチ・未コミット変更、ローカル設定とDBの移行、Orga向け開始メッセージ、Linearへの転記用タスクをまとめています。

仕様の基準は [実装計画書](docs/IMPLEMENTATION_PLAN.md)。方式の選定理由は [情報取得とAIの比較](docs/AI_AND_SOURCE_STRATEGY.md)、実装範囲と検証結果は [実装結果](docs/IMPLEMENTATION_REPORT.md) を参照してください。

2026-10-03の [チャット改善](docs/CHAT_IMPROVEMENTS.md) では、会話の引継ぎと納期の言い換え、PCでの専用領域、入力欄の非重複を修正しています。2026-10-06にJevの資料・分野判断とOpenAI/Geminiの回答生成を追加しました。AIの利用にはキー設定に加え、管理画面でプロバイダーの選択と接続確認が必要です。[AI接続手順・高速化の内容](docs/AI_SETUP.md) に、必要な操作と実装範囲を記載しています。

## 起動

Node.js 24 と npm を使用します。

```sh
npm install
npm run setup
npm run dev
```

公開ページ: http://localhost:3000 / 管理画面: http://localhost:3000/admin

`setup` が開発用の認証情報を `.env.local` に作り、ログイン用のランダムパスワードを `.local-admin.txt` に保存します。両ファイルはGit管理対象外です。管理画面へはそのパスワードでログインします。

初期状態は**デモモード**です。架空の確認用商品・価格を使い、注文送信は外部通信なしで記録されます。実際の会社の商品台帳、価格、在庫、販売条件、仕入先連携が検証済みであることを意味しません。

## 画面

- `/` — 企業案内と商品相談の入口
- `/products` — 商品検索と事業案内
- `/projects` — 現行サイトの写真による製作実績
- `/profile` — 会社概要
- `/contact` — 相談受付
- `/quotes/[token]` — 顧客用の見積確認と注文依頼
- `/admin` — 商品・情報源・仕入先・相談・見積・注文・設定・AI利用記録

旧サイトの `/products/`, `/profile/`, `/contact/` に対応するパスを維持しています。移行先はNext.jsが末尾スラッシュを正規化します。写真の取得元は [image-sources.json](docs/research/image-sources.json) に記録しています。

和文フォントはZen Kaku Gothic Newを同梱しています。取得元・ライセンスは [実装結果](docs/IMPLEMENTATION_REPORT.md#素材) に記録しています。

## 情報源を追加する

管理画面で情報源を追加し、信頼区分と公開区分を設定します。

| 種類                       | 操作                                                                    |
| -------------------------- | ----------------------------------------------------------------------- |
| Excel / CSV                | アップロード → プレビュー → 列の対応付け → 取込                         |
| PDF / Word / TXT           | アップロードし、抽出テキストを検索可能な文書として登録                  |
| Webサイト                  | 公開URLを登録して手動同期                                               |
| 公開CSV / スプレッドシート | CSVエクスポートURLを登録して同期                                        |
| REST API                   | 公開HTTPS URL、配列までのパス、列対応、必要なら認証用の環境変数名を登録 |
| 手動登録                   | 商品フォームまたは情報源のテキストを登録                                |

テンプレート: [CSV](public/templates/products.csv) / [Excel](public/templates/products.xlsx)。内容は架空の例です。確認日時は確認した日付を入力してください。テンプレートの日付を最新情報とみなさないでください。

列対応は `name: 商品名`, `model: 型番`, `price: 販売価格` のように、アプリの項目から元の列名を指定します。販売価格と原価を混同しないようにしてください。取込と販売承認は別の操作です。同じ情報源・メーカー・型番の商品は更新されます。

プレビューは先頭20行を返し、確定時に全行を処理します。URLから同期した更新情報は再確認が必要な状態になります。販売可能な根拠として使うには、管理画面で確認日時と承認を点検してください。

文書を取り込んだだけでは、商品を販売可能とは判定しません。画像だけのPDFには別途OCRが必要です。非公開のログインサイト、独自ERP/OAuth接続は個別のコネクター追加が必要です。

仕入・外注先の一覧は、情報源の種類「仕入・外注先一覧（Excel）」から取り込めます。会社名・取扱い品・HP・シート名・行番号を社内情報として保存し、売買金額は取り込みません。プレビューの「回答に使う分野」を確認して承認し、情報源の「承認済みの取扱分野をチャットの回答に使う」をONにすると、お客様への分野案内に使用します。会社名・HP・取引口座は公開せず、価格・在庫・納期等は担当者への相談につなげます。「登録内容」で確認でき、編集から回答利用を停止できます。

公開する分野名は定義済みの語彙に限定しています。未対応の分野は警告を表示し、回答に使いません。再取込は同じ情報源の一覧を置き換えるため、最新の一覧全体をアップロードしてください。HP本文の取得は行いません。実資料を使った検証結果と操作手順は [仕入先情報の登録・回答テスト](docs/SUPPLIER_KNOWLEDGE_REPORT.md) を参照してください。

## AI・検索の設定

環境変数にAPIキーを設定し、管理画面の設定でプロバイダーを選びます。キーがなくても社内商品検索・相談受付・見積/注文のデモ動作は確認できます。

価格・在庫・納期・数量計算・手続き案内はローカルで回答します。用途や仕様の相談にAIを使い、両方が混在する質問では登録値の本文に相談の補足を追加します。[質問ごとの振り分け表](docs/CHAT_ROUTING.md) を参照してください。

| 環境変数                | 用途                                             |
| ----------------------- | ------------------------------------------------ |
| `TYPESAFE_API_KEY`      | Jevによる問い合わせ・分野・資料の判断            |
| `TYPESAFE_API_BASE_URL` | Jevの接続先。直接TypeSafeまたはVercel AI Gateway |
| `OPENAI_API_KEY`        | OpenAIによる回答生成・段落ごとの途中表示         |
| `GEMINI_API_KEY`        | Geminiによる問い合わせ意図の抽出・回答生成       |
| `EXA_API_KEY`           | Exaによる公開Web検索                             |
| `TAVILY_API_KEY`        | Tavilyによる公開Web検索                          |

Jevは取扱分野と資料候補の関連性を判断し、OpenAI/Geminiが根拠と会話履歴から文章を作ります。Web検索はExa/Tavilyが担当します。販売可否・金額・在庫・注文条件はサーバーのルールで検証します。管理画面にキーの有無と、実際のAPIによる接続確認を用意しています。手順は [AI接続](docs/AI_SETUP.md) を参照してください。

Vercelで発行したAI GatewayキーをJevに使う場合は、`TYPESAFE_API_BASE_URL=https://ai-gateway.vercel.sh/typesafe` を設定します。直接TypeSafe発行なら既定値 `https://api.typesafe.ai` を使います。[Vercel発行キーの401原因・接続先修正・同一48問の比較](docs/VERCEL_JEV_FIX_2026-10-07.md)を参照してください。

OpenAIとJevの呼び出しは、管理画面の「AI利用記録」（`/admin?tab=ai-usage`）で確認できます。用途・モデル・HTTP状態・採用/不採用・検証拒否理由・所要時間・送信JSONの構造とサイズ・取得できたトークン使用量を保存し、質問/会話IDと対応づけています。APIキー・リクエスト本文は利用記録に保存しません。記録開始前の使用量や、提供元から返らなかった使用量は復元しません。失敗・不採用でも呼び出し回数に含み、取得済みトークンのみ合算します。[追加48問の試験とAPI利用量](docs/AI_USAGE_AND_EXTRA_TESTS_2026-10-07.md)、[専用キー設定後の同一48問比較](docs/JEV_RETEST_COMPARISON_2026-10-07.md) を参照してください。

情報源の認証用変数名には `SOURCE_`、仕入先の署名用変数名には `SUPPLIER_` から始まる名前を使います（例: `SOURCE_VENDOR_TOKEN`, `SUPPLIER_VENDOR_SECRET`）。値はサーバー環境変数に設定し、管理画面には変数名だけを登録します。

## 機能設定

チャット、Web検索、価格/在庫/納期表示、見積受付、自動見積、注文、自動承認、担当者引継ぎを切り替えます。自動見積は見積受付、注文は見積受付、自動承認は注文に依存します。設定はDBに保存され、公開APIでも適用されます。

見積は「依頼 → 下書き → 発行 → 顧客の注文依頼」、注文は「承認待ち → 承認 → デモ送信/実送信」の順です。顧客が送信した価格は採用せず、保存済みの明細から合計を計算します。専用見積リンクは秘密情報として扱ってください。

## 同期とデータ保存

```sh
npm run sync
```

有効なURL情報源のうち更新間隔を過ぎたものを同期します。定期化する場合はcron等からこのコマンドを起動してください。アップロード型情報源は新しいファイルを取り込みます。

SQLite DBと関連データは `DATA_DIR`（標準 `.data`）に保存します。永続ディスクを持つ単一Nodeサーバーで動かしてください。複数インスタンスやサーバーレス運用へ移す場合はDB/ジョブ構成の変更が必要です。

Vercel用の面談プレビューは架空の商品だけを使い、SQLiteを一時領域に置きます。会話や設定は消える場合があり、実商品・社内データ・本番運用には使えません。公開手順と本番化前の設定は [Vercelデプロイ手順](docs/VERCEL_DEPLOYMENT.md) を参照してください。

リバースプロキシを使う場合、`APP_ORIGIN` をブラウザーが使う公開オリジンに合わせます。`TRUST_PROXY=true` は、プロキシが利用者から届いた転送ヘッダーを上書きする構成でのみ指定してください。未指定時は転送ヘッダーを信用せず、レート制限を共通のローカル枠で適用します。

バックアップはアプリと同期を停止してデータディレクトリをコピーするか、SQLiteのバックアップAPIを使用してください。WAL運用中のDB本体だけをコピーすると未反映データが欠ける可能性があります。

## 実運用への接続

1. 実際の商品台帳と仕入先を登録し、公開範囲・取扱承認・確認期限を点検する。
2. `APP_ORIGIN` を公開HTTPSオリジンに変更し、認証秘密を本番用に設定する。
3. 必要なAI/検索APIキーと仕入先の認証情報をサーバー環境変数に設定する。
4. 仕入先の注文APIとペイロード・署名・冪等キーの扱いを合わせる。
5. 実APIとの接続テスト、データ管理方針と注文上限を確認する。
6. デモを終了する場合は `DEMO_MODE=false`。実発注を有効にする場合のみ `ALLOW_LIVE_ORDERS=true` とし、管理画面の注文設定も有効にする。

汎用注文連携は署名付きJSON Webhookです。取引先の既存システムがそのまま受信できるとは限らず、専用変換処理が必要な場合があります。今回、実発注・実メール送信・公開ドメインの変更は行っていません。

## 開発・検証

```sh
npm run typecheck
npm test
npm run build
npm run test:e2e
```

E2Eはポート3210と `/tmp/aoki-eng-e2e-*` の独立したDBを使用し、デモモードで実行します。Chromiumがなければ `npx playwright install chromium` を実行してください。

拡張する際は `lib/contracts.ts` と計画書のAPI契約を合わせて更新します。情報源は `lib/server/connectors.ts`、モデル/検索/注文先連携は `lib/server/providers.ts` のインターフェースに追加します。Web/資料の内容を命令として実行しないでください。
