# 商品・製作の取扱確認 — ローカル実装

設計版1.1、契約バージョン2を基に、新しい空のリポジトリから作成した独立アプリです。既存チャットのコード・API・DB・Cookie・プロンプトを利用しません。

短い聞き取り → 協力会社マスタ照合 → 正常に候補ゼロの場合だけWeb検索 → 担当者確認とお客様向け回答・メール文をローカルで操作できます。照会先の適合条件と自社の承認済み取扱条件を個別に表示します。

お客様への返答を、保存した条件・訂正内容・資料で確認できない具体条件に沿う文章へ改善しました。入力済みの値を「未入力」として聞き直さず、結果とメールに同じ説明と次の行動を表示します。[実画面の短いトーク記録](docs/CUSTOMER-TALK-20261117.md)と[検証報告](docs/CUSTOMER-REPLIES-20261117.md)を参照してください。ローカル231件成功で、新しい実モデル出力の評価とは区別します。

## 起動

Node.js 24で検証しました。依存はpackage-lock.jsonで固定しています。

```bash
cd /home/uta/aoki-availability-v2-local-20261116
npm ci
npm run db:migrate
npm run dev
```

この環境の `http://127.0.0.1:8787` を開きます。D1・R2・Queueはローカルエミュレーターです。アカウント登録・ログイン・Cloudflareリソース作成は不要です。

従来の架空ルールを使うデモを試す場合は、別のターミナルで次を実行します。協力会社の実マスタを使う場合は下の「協力会社マスタ」を参照してください。

```bash
npm run demo:seed
```

または画面右上「管理」でローカル管理トークン `availability-local-admin` を入力し、「デモ資料を準備」を押します。この固定トークンはローカル専用で、ループバック以外ではアプリ自体が起動を拒否します。

`npm run dev` はUIビルド後にWorkerを起動し、5秒ごとにWranglerのローカル専用scheduledイベントを駆動します。outbox回復、期限切れleaseの再配信、60秒期限、保管期限・削除予約を処理します。UI変更後は再起動すると静的資産が更新されます。停止はCtrl+Cです。

## 動作例

- `AX-100を購入したい`：追加質問0、架空の個別承認に基づく対応可能。
- `名前不明の交換部品です`：補助質問、不明・スキップから担当者確認へ。
- `図面の架台を製作したい。塗料は支給。来月上旬を希望`：取扱分野は対象、今回の製作条件は確認待ち。
- `リング材を支給するので穴加工してほしい`：架空の方式別対応外。「入力内容を確認・修正」で材料手配を当社調達へ変更して再調査すると、旧方式の不可を流用しません。
- 改行で4品目以上入力：全入力を保持し、先頭3品目までを新しい相談へ分割。残りは元の案件へ保持します。

既定の自由文は小さなデモ抽出器です。実API向けに軽量モデルと短い差分形式を選べます。GPT-6 Lunaの実比較では両形式とも品質1/3件でしたが、型番の欠落・数量引用・複数品目の帰属を修正し、**保存した6応答の再生は6/6件合格**しました。保存中に次の回答が消えるUI競合も修正しました。[原文対応の修正と再生結果](docs/OFFLINE-FAST-REPAIR-20261117.md)を参照してください。新しいモデル出力・速度は再評価しておらず、**実用合格には達していません。**

2026年11月20日から、通常のローカルプレビューは `INTAKE_UNLIMITED_LOCAL=true` で累計・案件別のAI呼出し回数制限を解除しています。既存の使用回数・利用量は引き続き記録します。`npm run intake:status` の `unlimitedLocal: true` で確認できます。ローカル版の OpenAI 聞き取りには30秒の応答期限を設け、同じ操作の再送による二重呼出しを防ぎます。認証失敗・429時は追加呼出しを止めます。

11月16〜17日の追加評価枠は累計40/40生成、保守的費用予約0.929633米ドルで終了しました。これは過去の比較評価runnerの記録で、通常プレビューの現在の回数設定とは別です。[軽量モデル比較](docs/LIVE-FAST-INTAKE-20261117.md)と、以前の[修正・再検証](docs/LIVE-REPAIR-20261116.md)を参照してください。

元発言・変更前後は非公開で保持します。未確定の相談や解釈失敗が残る場合は、最新原文をメールへ載せ、旧条件・旧判定は確定表示しません。一般の日本語相談を網羅するモデルとしての品質や、会社の実際の判断は保証していません。設定は[自由文抽出の接続手順](docs/INTAKE-INTEGRATION.md)を参照してください。

## 実装済みの境界

- 4プロフィール、一問中心。品目別に不足条件を確認し、質問回数だけでは終了しません。不明・スキップ済みの項目は聞き直さず、未解釈の返答は同じ確認を2回まで試して他の条件へ進みます。選択操作はAI・検索・OCRを呼びません。
- 品目IDと属性辞書による更新、訂正履歴、単位・引用・列挙値の検証。不明・スキップの保存。
- `scopeAssessment` と `verdict` の独立判定。期限、承認、資料の役割、個別依頼の必須条件、競合を検証。
- 新しい匿名セッション、Origin/CSRF対策、所有権、頻度制限、revisionと冪等性。
- D1 batchのCASガード、outbox、Queue、lease、期限・知識版・入力版を照合した結果commit。
- 非公開のローカルR2保存、MIMEとシグネチャ・容量検査、所有権、添付差替え、期限・削除処理。PDFはダウンロード扱い。
- 公開結果はallowlist DTO。結果取得とメール生成時に根拠を再検証し、古い肯定を失効。
- ルールのJSON編集・検証・承認状態/期限の更新、撤回。原資料メタデータの登録。管理APIによる案件閲覧。
- メール宛先未設定時も全文コピー可能。宛先設定時のmailto生成とURI長超過時の短縮。送信処理はありません。

## 未接続の機能・今回の合格範囲

実モデル用の抽出adapterと軽量モデル向け差分形式は実装済みです。単発接続・架空20相談の評価、修正版10相談、軽量モデル6回の比較を実施しましたが、品質・速度を両立できていません。独立した未知相談での評価は未実施です。外部検索と公開ページの本文取得は個別の接続設定が必要です。OCR・画像/PDF内容解析は未接続です。添付は「受領済み・未解析」とし、添付を使う調査はpartial、対象品目は確認待ちにします。数値・型番を読んだことにはしません。

仕入先情報はローカルマスタとして取り込みます。過去の実メールと現在の会社承認情報は同梱していません。実モデルでは接続確認・予備3相談・追加比較4回/固定20相談・修正版10相談を実施しました。独立した未知の20相談・会社担当者による判断一致・実端末評価は未実施です。本番用管理者JWT検証・インフラID・費用上限・外部資料利用許可・宛先・会社の保管方針も未設定です。実モデル抽出は、`INTAKE_PROVIDER=openai`、`EXTERNAL_ENABLED=true`、利用許可のあるAPIキー・モデル名・出力トークン上限と、回数上限またはローカル専用の制限解除を明示した場合のみ有効です。検索・添付解析はこれらの設定では有効になりません。

実資料を使った試用はローカルが対象です。本番サイト内の管理者試用は架空資料の構成です。

ローカルの検証コマンドは本番への配信を行いません。`npm run build` 内の `wrangler deploy --dry-run` はローカルでbundleを作るだけです。

## 協力会社マスタ

Node.js 24 と Python 3（XLSX 読み取り用の標準ライブラリ）を使用します。ローカルD1にマイグレーションを適用した後、同じマッピングでプレビューと登録を実行します。

```bash
npm run db:migrate
npm run partners:import -- --file "/mnt/c/Users/uta/Downloads/【重要】36期_売買集計表（仮）.xlsx" --mapping config/partner-mappings/purchasing-ledger.json --preview
npm run partners:import -- --file "/mnt/c/Users/uta/Downloads/【重要】36期_売買集計表（仮）.xlsx" --mapping config/partner-mappings/purchasing-ledger.json --apply
```

このブックは「仕入」シートで仕入先、取扱い品、HPを対応づけます。月別欄や工番は取り込み対象外です。仕入先名だけの行は一覧に残ります。同じCLIでCSVも取り込めます。列や設備が異なる資料には別のマッピングを渡してください。たとえば旋盤ごとの最大外径を表すことが確認済みの列は、次のように対応づけます。

```json
{
  "sourceKey": "加工設備一覧",
  "headerRow": 1,
  "columns": {"name": "会社名", "website": "ウェブサイト"},
  "capabilities": [
    {"kind":"processing","group":"設備","groupColumn":"設備番号","field":"process","column":"加工種別"},
    {"kind":"processing","group":"設備","groupColumn":"設備番号","field":"material","column":"対応材質","separator":"、"},
    {"kind":"processing","group":"設備","groupColumn":"設備番号","field":"dimension","column":"対応外径","axis":"outer_diameter","numeric":true,"bound":"max","unit":"mm"}
  ]
}
```

再取り込みでは同じ資料に同じ `sourceKey` を使います。同じ内容と出典なら版は進みません。別資料の対応条件は保持し、同じ条件を裏づける出典は併記します。最新取込みが失敗した場合は旧版を保存したまま照合を保留し、正常な取り込みで再開します。

加工・製作の依頼でも、注文品や材料に該当する取扱い品を調達先候補として照合します。たとえば「耐熱ガラスの部品」に対して「ガラス製品」の記載があれば、担当者は材料の手配先として確認できます。耐熱仕様、指定寸法、数量への対応や製作可否は個別に確認します。調達先が要確認候補に残る場合もWeb検索は開始しません。

購入では、スプレーノズルチップに対する「ノズル製品他」、断熱ブランケットに対する「断熱材等」、ガラス容器に対する「ガラス製品」のように、台帳に上位の分類だけがある場合も、元の記載と行を添えて担当者の要確認候補に残します。指定品や個別仕様を取り扱えるかは仕入先への照会事項になります。

「管理」でトークンを入力して「読み込む」を押し、「仕入先一覧を読み込む」または案件を選択してください。会社・条件組ごとの一致、不足、範囲外、元ファイル・シート・行を表示します。お客様向けのAPI・メールには仕入先台帳の行を出力しません。裁量で公開する取扱情報は、別途、既存の承認ルールに登録します。

ローカルWeb検索は初期状態で停止しています。接続する場合は `.dev.vars.example` を参照し、外部利用と `PARTNER_WEB_ENABLED` を有効にしてBrave Searchの専用キーを設定します。案件内の全品目でマスタ照合が正常完了し、一致と要確認の両方が0件の場合だけ、検索用に構造化した条件を送信します。直接取得する本文は `PARTNER_WEB_ALLOWED_HOSTS` に設定したホストが対象です。新しく発見した会社も調べる場合は `PARTNER_WEB_READER=jina` を指定すると、その検索結果URLをReaderへ渡して本文を取得します。お客様の画面・メールへの引用を許可するホストは `PARTNER_WEB_PUBLIC_HOSTS` に完全なホスト名で設定します。本文で確認できた事実と未確認の条件は別々に表示されます。検索の利用上限・設定例は[Web調査設定](docs/partner-web-configuration.md)を参照してください。

### 仕入先に照会できるところまで聞き取る

ローカルで協力会社マスタの取り込みが完了した案件では、次の順で一問ずつ確認します。一度に受け取った複数の条件は品目別に保存し、該当する質問を飛ばします。

| 依頼 | 基本の確認順 |
| --- | --- |
| 購入 | 品物の特定（型番が不明なら用途・材質・品物に合う寸法）、数量と単位、希望納期 |
| 加工・製作 | 対象と加工内容、材質、加工に効く寸法、数量と単位、希望納期、材料手配。図面・公差が関係するときはそれも確認 |

自由文は、直前の質問と品目ごとの保存済み条件を OpenAI に渡して、一度の発言から複数の項目を更新します。聞き取り中の画面に受領済み条件を表示します。たとえば円筒の製作で外径・全長が判明済みなら、中空・中実を確認します。中空で内径も同時に答えたら、その両方を記録して次の未確認項目に進みます。

ローカルの OpenAI が時間切れの場合も、原文から対象と条件が一意に確かめられる入力はローカルで取り込みます。以前の最初の入力で抽出に失敗し、その後編集していない相談も、画面を開いたときに同じ条件で復元します。処理できない文が独立している場合は、確認できた条件を先に保存し、保留箇所を示して聞き返します。

断熱ブランケットの厚さ・幅・長さ、架台の幅・高さ・奥行、リング穴あけの穴径・穴数・配置、型番未定のガラス容器の容量を、品目に応じて個別に聞きます。調査に進んだ時点でこれらの項目に不足があれば、担当者に項目名と不明・スキップなどの状態を渡します。旋盤の外径と全長、板の厚さと縦横も個別に扱います。未定やスキップを記録した項目は再入力を求めません。基本項目と有効な承認済みルールの確認が済み、品物を探す手掛かりがあると自動調査を開始します。「この内容で調べる」から途中でも調査できます。

調査後にお客様の回答で候補が変わり得る場合は、一度に一問だけ表示します。指定型番で候補を確認できず、品種を特定できている場合は同等品を含める許可を伺います。許可または新しい条件を受けた場合は同じ相談で再照合します。「指定型番のみ」「分からない」「回答をスキップ」では結果を保持します。仕入先の在庫・対応可能な数量・納期など、仕入先側の情報不足は管理画面の確認事項に表示します。

## ルール取込

原資料メタデータを管理画面で登録後、CapabilityRuleの配列JSONまたはCSVを読み込みます。既定は検証のみです。

```bash
npm run rules:import -- fixtures/demo/knowledge.json
npm run rules:import -- rules.csv
npm run rules:import -- rules.json --apply
```

CSVのヘッダーはCapabilityRuleのフィールド名です。`predicates` / `modelAliases` / `requiredFields` / `coveredFields` 列はJSON、`isDemo`はtrue/false、`version`は整数です。空の承認者・承認日時・有効期限はnullです。CSV内のJSONは通常のCSV引用規則で引用してください。既存ルールの更新はversionを増やします。承認・撤回は `approvalStatus` を更新し、保存前に検証プレビューで対象・依頼方式・根拠・公開説明を確認します。

管理APIはループバック限定の `X-Local-Admin-Token` と匿名セッションを必要とし、更新にはOrigin/CSRF検証を適用します。ローカル保存先は `.wrangler/state/`、Gitには入りません。案件・添付は作成から30日、本文を含まない監査は90日を暫定値としています。

```bash
npm run check

```

| コマンド | 検証対象 |
| --- | --- |

| `test:contracts` | 契約版2、不正な肯定、余分な公開フィールドの拒否 |
| `test:domain` | 聞き取り・更新・分野/個別判定・公開DTO・メール文・抽出障害 |
| `test:integration` | 実ローカルD1/R2、CAS競合・outbox・lease・失効・権限・分割 |
| `test:e2e` | ChromiumのPC/モバイル表示、4プロフィールとメール文までの操作 |
| `test:isolation` | 旧コード・旧API・セッションへの依存と許可外endpointの検出 |
| `build` | Vite資産・Workerのdry-run bundle |
| `measure:local` | 外部処理なしの選択100操作・自由文30入力・調査20案件 |

E2E・速度測定は、専用の`127.0.0.1:8788`で別DB・キーなしのdemo環境を自動起動します。通常プレビューの`.dev.vars`とAPI枠は使いません。実APIが有効な環境へ接続した場合は開始前に中止します。メールソフトも外部送信も起動しません。`playwright.config.ts` はlocalhostだけを使います。ブラウザが未導入なら `npx playwright install chromium` を実行してください。

詳しい検証結果・制約は [docs/LOCAL-VALIDATION.md](docs/LOCAL-VALIDATION.md)、測定値は [docs/LOCAL-MEASUREMENTS.json](docs/LOCAL-MEASUREMENTS.json) にあります。

## 構成と設計資料

`src/domain/` は判定・更新、`src/adapters/` はローカル保存と抽出、`src/http/` はAPIと認証、`src/ui/` は画面です。`src/worker.ts` がHTTP、`src/research-worker.ts` がQueueと保守を扱います。同じローカルWorkerで両ハンドラを実行し、domainはCloudflare APIに依存しません。

原本を変更せずコピーした [docs/design/README.md](docs/design/README.md) から設計版1.1を参照できます。実装上の補足は [docs/IMPLEMENTATION-NOTES.md](docs/IMPLEMENTATION-NOTES.md) に記録します。
